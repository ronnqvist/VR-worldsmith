# Project: "Worldsmith" — Voice-Prompted Generative A-Frame WebXR Worlds

You are an expert web developer. Build a complete, production-quality WebXR
application based on this specification. Output the full project, file by file,
with no placeholders.

## 1. Core Concept

A single-page WebXR app where the user, inside VR, speaks natural-language
prompts (e.g. "create a floating island with waterfalls and glowing crystals"
or "make the sky sunset-colored and add birds") and an LLM generates or updates
the world in real time. THE LLM OUTPUTS PURE A-FRAME MARKUP — declarative HTML
entities only. No JavaScript and no CSS are ever generated by the LLM or
required from it; the client injects sanitized A-Frame markup directly into
the scene. All interactivity comes from A-Frame's built-in components
(animation, sound, light, material, geometry, text, gltf-free primitives).

## 2. Target Devices & Session Modes

- Primary target: Meta Quest 2 via the built-in Meta Quest Browser. Must also
  work on Quest 3/Pro, desktop Chrome/Edge with a headset, and a full non-VR
  desktop mode (A-Frame's default mouse/keyboard controls).
- Default session: `immersive-vr` (A-Frame handles this natively).
- Secondary, opt-in: mixed-reality passthrough via `immersive-ar`. Detect
  support with `navigator.xr.isSessionSupported('immersive-ar')` before
  showing an "MR mode" toggle. Requirements:
  - WebGL renderer `alpha: true`, transparent clear color, transparent canvas
    background CSS.
  - In MR mode, strip/ignore any `<a-sky>` in generated markup and instruct
    the LLM (via system prompt) not to emit sky or ground planes.
  - Quest 2 passthrough is grayscale (color on Quest Pro/3) — don't rely on
    real-world color cues.
  - No plane detection or anchors in v1 — note as a commented extension point.
- Performance budgets for Quest 2 (XR2-class GPU): target stable 72+ fps,
  max ~200 entities, prefer `<a-icosahedron>`/low-`segments-*` geometry,
  no real-time shadows by default, cap pixel ratio at 1.5.

## 3. Tech Stack

- A-Frame (latest stable) as the ONLY rendering framework, loaded via npm.
  Three.js is used only indirectly through A-Frame (a couple of small escape
  hatches in client code are acceptable, e.g. renderer configuration).
- Vanilla JS + ES modules, built with Vite. Static site, HTTPS required.
- Voice input: Web Speech API (`SpeechRecognition` /
  `webkitSpeechRecognition`) where it works. SpeechRecognition is absent in
  Meta Quest Browser, so the client must also record the microphone itself and
  transcribe the clip with an audio-capable OpenRouter model (sent as an
  `input_audio` WAV part; default `google/gemini-3.1-flash-lite`, reasoning
  off). An in-VR virtual keyboard fallback is still REQUIRED as the last
  resort. Detect availability at startup and route automatically.
- Ambient audio: the client pre-generates one short procedural ambient loop
  via the Web Audio API at startup, registers it as an `<audio>` asset with
  id `generated-ambient` in `<a-assets>`, and any entity in LLM markup may
  reference it via `sound="src: #generated-ambient"` (this is the only audio
  source the sanitizer allows — no other `src` values are permitted).
- No build-time secrets. No server.

## 4. LLM Integration (OpenRouter only)

- Endpoint: POST https://openrouter.ai/api/v1/chat/completions
  (OpenAI-compatible).
- Default model: `anthropic/claude-sonnet-5.5` (~$2/1M input, $10/1M output,
  1M context). Model ID is a configurable setting (dropdown of defaults —
  Claude Sonnet 5.5 and the newest Grok, `x-ai/grok-4.7` — + free-text field).
- Reasoning effort is a configurable setting, sent via OpenRouter's
  `reasoning` parameter. Supported levels differ per model, so the dropdown
  shows only the levels the selected model supports (from the OpenRouter model
  catalogue), plus "Auto" (recommended level) and "Provider default"
  (parameter omitted).
- Voice engine (auto / browser speech recognition / OpenRouter transcription)
  and transcription model are configurable settings.
- The user enters their own OpenRouter API key (`sk-or-v1-...`) in settings,
  available both in the 2D DOM overlay and via the in-VR panel. Stored ONLY in
  `localStorage`, sent only to `openrouter.ai`. Include a "Validate key"
  button that fires a minimal test request and reports success/failure.
- Optional configurable `HTTP-Referer` and `X-Title` headers.
- Request strict JSON via `response_format: { type: "json_object" }` with the
  response envelope defined in section 5.
- Streaming OFF by default; retry once on 429/5xx with exponential backoff.
  Clear in-VR error messages (e.g. "OpenRouter rejected your key").

## 5. LLM Output Contract (A-Frame markup inside JSON)

The model returns JSON of exactly this shape:

{
  "action": "create_world" | "update_world",
  "markup": "<a-entity ...>...</a-entity>",
  "removed_ids": ["entity_id_1"],
  "narration": "One short spoken-style sentence about what changed."
}

Rules enforced via the system prompt (stored as an editable constant in
`src/llm/systemPrompt.js`):

- `markup` contains ONLY A-Frame markup: `<a-scene>` children such as
  `<a-entity>`, `<a-box>`, `<a-sphere>`, `<a-cylinder>`, `<a-cone>`,
  `<a-plane>`, `<a-icosahedron>`, `<a-sky>`, `<a-light>`, `<a-text>`, and
  animation ONLY via the `animation` component attributes (e.g.
  `animation="property: position; to: 0 2 0; dir: alternate; loop: true"`).
  Also allowed built-in components: geometry, material, light, position,
  rotation, scale, animation, sound (src may only reference the token
  `#generated-ambient`), text, fog, and `class="interactive"` for grabbable
  objects.
- Every entity must carry a unique `id` so updates and removals can target it.
- FORBIDDEN in markup: `<script>`, `<style>`, `<link>`, `<img>` with external
  URLs, any `on*` event-handler attributes, any `src`/`gltf-model`/`obj-model`
  pointing at network URLs, any custom components not in the whitelist.
- `create_world` replaces the whole generated-world container;
  `update_world` entities are merged by id (existing id = replace that
  entity's markup; new id = append; `removed_ids` = delete).
- Limits told to the model: max 200 entities total, positions within ±100 m,
  no entity scaled beyond 50 m, low-poly geometry settings.

Client-side pipeline for every response:

1. Parse JSON; on failure show the error and keep the current world.
2. Sanitize `markup` with a whitelist-based sanitizer (parse via DOMParser,
   walk the tree, drop non-whitelisted tags/attributes/components, reject if
   anything forbidden is found). NEVER inject raw LLM output unsanitized.
3. Inject into a dedicated container: `<a-entity id="generated-world">` inside
   the app's own `<a-scene>` (which also holds the rig, controllers, UI).
4. Apply transitions: fade/scale-in newly added entities via A-Frame
   `animation` attributes added client-side (the LLM needn't do this).

## 6. Voice Interaction Loop

1. Hold the left controller trigger (or tap the mic orb on the left
   controller) to listen; release to stop. The pulsing mic orb, mounted on
   the left controller, shows state: listening / thinking / speaking.
2. Web Speech API transcribes WHEN AVAILABLE; otherwise the recorded clip is
   transcribed through OpenRouter (see section 3). Only if neither works (no
   microphone, permission denied, no API key, or keyboard input chosen) does
   it open the in-VR virtual keyboard (ray-interactive QWERTY panel, large
   "Send" button). Never leave the user without an input path.
3. Transcript + compact serialization of the current generated world (its
   current markup, truncated sensibly) → OpenRouter → JSON envelope → sanitize
   → inject with smooth transitions.
4. `narration` is spoken via `speechSynthesis` when available (mute toggle
   respected); otherwise shown as a floating text caption.
5. Stable frame rate always; LLM latency masked by an ambient "dreaming"
   particle swirl (implemented client-side as a pre-built entity toggled
   visible during waits — not LLM-generated).

## 7. VR UX Details

- A-Frame movement: `movement-controls` or a small custom component — smooth
  locomotion on left thumbstick, 45° snap turn on right, comfort vignette
  toggleable.
- Interaction: laser pointer from right controller; entities with
  `class="interactive"` can be grabbed/moved with the right trigger (simple
  grab component); squeezing the grip while holding deletes (with 3-second
  undo toast). Left controller: hold trigger to talk, Y toggles the wrist
  panel, X opens the virtual keyboard.
- Wrist-mounted panel (left hand): Listen, Keyboard, Settings, History (last
  20 prompts), Undo (revert last update — keep the previous world markup in
  memory), Export, Import, Reset World, MR toggle (if supported).
- 2D DOM interface mirrors everything for desktop/non-VR: text prompt box,
  orbit camera (A-Frame default look-controls), all panel features. Fully
  usable without a headset.

## 8. Persistence (local only — no backend)

- `localStorage` holds: API key, settings, current world markup, prompt
  history, named saved worlds.
- Export: one `.worldsmith.json` (settings minus API key, saved worlds,
  history). Works from the 2D UI; in-VR export triggers browser download.
- Import: file picker, schema validation, merge/replace choice.
- Storage behind a clean async `StorageProvider` interface so a future backend
  (e.g. Convex) swaps in without touching app logic — mark with a comment.
